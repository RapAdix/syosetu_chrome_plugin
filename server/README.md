# Japanese Grammar Assistant — Cloudflare Worker Backend

This directory contains the Cloudflare Workers backend and Cloudflare D1 database that power the server provider option for the Syosetu Chrome extension.

---

## 1. Deploying Worker Code Changes

All code changes to `server/src/index.ts` or the shared prompt file (`prompts.js`) are bundled and deployed using Wrangler.

```bash
cd server

# Deploy to Cloudflare Workers (production)
npm run deploy

# Run local development server
npm run dev
```

## 2. Managing Users & Passwords

User authentication uses salted PBKDF2-SHA256 password hashing (100,000 iterations). Passwords must never be stored in plain text.

### Generate a Password Hash & SQL Commands

Use the local hashing CLI script:

```bash
# General syntax:
npm run hash-password -- <username> <password> [daily_limit]

# Example:
npm run hash-password -- alice SuperSecretPassword123 150
```

The script generates the hash and outputs pre-formatted `wrangler d1 execute` commands for both remote and local databases.

### Creating a New User

Execute the command generated by `hash-password`:

```bash
# Remote (Production)
npx wrangler d1 execute DB --remote --command="INSERT INTO users (username, password_hash, daily_limit) VALUES ('alice', 'pbkdf2$100000$...', 150);"

# Local (Development)
npx wrangler d1 execute DB --local --command="INSERT INTO users (username, password_hash, daily_limit) VALUES ('alice', 'pbkdf2$100000$...', 150);"
```

### Updating an Existing User's Password

```bash
# Remote (Production)
npx wrangler d1 execute DB --remote --command="UPDATE users SET password_hash = 'pbkdf2$100000$...' WHERE username = 'alice';"

# Local (Development)
npx wrangler d1 execute DB --local --command="UPDATE users SET password_hash = 'pbkdf2$100000$...' WHERE username = 'alice';"
```

### Listing Existing Users

```bash
# Remote (Production)
npx wrangler d1 execute DB --remote --command="SELECT id, username, is_active, daily_limit, requests_today, last_request_date FROM users;"

# Local (Development)
npx wrangler d1 execute DB --local --command="SELECT id, username, is_active, daily_limit, requests_today, last_request_date FROM users;"
```

## 3. Database Schema & Migrations

The database schema is defined in `server/schema.sql`.

### Initial Table Creation

To initialize a brand new database from `schema.sql`:

```bash
# Remote (Production)
npm run db:init:remote

# Local (Development)
npm run db:init:local
```

### Modifying Schema (Adding Columns Without Data Loss)

Cloudflare D1 runs SQLite. When adding columns to existing tables in production without dropping existing data, run `ALTER TABLE` commands:

```bash
# Example: Adding a new column to users
npx wrangler d1 execute DB --remote --command="ALTER TABLE users ADD COLUMN notes TEXT DEFAULT '';"
```

> **Important**: Always update `server/schema.sql` at the same time so new database initializations stay in sync.

## 4. Managing Worker Secrets

Secrets are stored securely in Cloudflare's encrypted secret store and injected into Worker environment bindings at runtime. They are not stored in `wrangler.toml` or source code.

```bash
# Set Gemini API key
npx wrangler secret put GEMINI_API_KEY

# Set JWT secret used for signing user tokens
npx wrangler secret put JWT_SECRET
```

When prompted by Wrangler, paste the respective secret key.
